# Backend/API

- Изучи существующий backend и следуй текущему стеку; не добавляй второй сервер без необходимости.
- Организуй слои routes/controllers → application services → domain rules → repositories/integrations.
- Валидируй body/query/params на границе схемами; нормализуй ошибки.
- Каждый endpoint защищён аутентификацией и авторизацией на сервере.
- Не доверяй userId/role/shiftId/permission из клиента без проверки связи с текущей сессией.
- Используй транзакции для связанных изменений: назначение в отряд, импорт, ответы опроса, смена статуса.
- Реализуй пагинацию, фильтры, сортировку и ограничения размера запросов.
- Учитывай idempotency для Telegram notifications и повторных запросов.
- Не возвращай лишние поля PII; применяй DTO/allowlist.
- Не раскрывай stack traces и внутренние ошибки в production.
- Добавь integration tests на позитивные и негативные сценарии.
