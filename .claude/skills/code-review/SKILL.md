# Code review

Проверяй diff, а не только итоговый код:
1. Сохранены ли существующие пользовательские сценарии?
2. Нет ли фиктивной реализации, mock data или TODO в production path?
3. Все ли API операции защищены сервером и проверяют scope ресурса?
4. Нет ли утечки PII/secrets, небезопасных URL или публичных файлов?
5. Согласованы ли схема, миграции, DTO, frontend types и тесты?
6. Есть ли обработка loading/error/empty/permission denied?
7. Корректны ли транзакции, уникальность и повторные запросы?
8. Не выросли ли bundle/latency без причины?
9. Проверены ли мобильные состояния Telegram WebView?
10. Проходят ли lint/typecheck/tests/build?
Сначала сообщай блокирующие P0/P1 с конкретными файлами/строками. Не делай косметический рефакторинг в том же diff, если он затрудняет проверку критичного изменения.
