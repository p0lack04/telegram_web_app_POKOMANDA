# QA and testing

- Сначала зафиксируй baseline: lint, typecheck, unit, integration, e2e, build.
- Пиши тесты доменных правил независимо от UI.
- Для RBAC проверь каждую роль/должность и доступ к чужой смене/отряду/профилю.
- Для Telegram auth проверь валидную подпись, изменённые данные, просроченный auth_date, неверный hash.
- Для onboarding проверь статусы PENDING/CONFIRMED/REJECTED и запрет доступа до подтверждения.
- Для импорта проверь дубликаты, пустые поля, неверные даты, большие файлы, формулы и rollback.
- Для файлов проверь MIME spoofing, oversized, unauthorized download и удалённые файлы.
- Для опросов проверь audience, required questions, duplicate submission и закрытый опрос.
- Для DailyMark проверь уникальность и разрешённые типы/даты.
- E2E покрывает главные потоки ADMIN, LEAD, TRAINEE на мобильном viewport.
- После изменений запускай минимальный релевантный набор, перед завершением — полный доступный набор.
- Не маскируй flaky tests и не удаляй тест ради зелёного CI без анализа причины.
